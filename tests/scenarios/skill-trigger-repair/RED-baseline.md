# RED baseline — skill-trigger-repair (no skill present)

Model: **sonnet**, pinned on every dispatch. Date: **2026-09-01**.

Fresh `general-purpose` subagents, scenario text only, one isolated scratch repo each
(`/tmp/acme-skills-red{1,2,3}`, seeded by `fixtures/seed-repo.sh` from
`fixtures/debriefs/`). Recorded verbatim; honest RED — **all three chose (B)**, and the
choice letter is a pass in every run. The failures are in what they produced, and they
repeat across runs.

The seeded corpus supports exactly this: `capture-lesson` 3 dates / 4 bullets with the
user's own words quoted each time, `lean-debugging` 2 dates with user words,
`lean-verification` 2 dates with *only its own description* quoted back, and
`prisma-safety-review` + `lean-brainstorming` at 1 date each. `capture-lesson` and
`lean-debugging` are absent from all three routing surfaces.

## Scenario 1 (owner demands a same-morning fix to a once-missed skill) — PARTIAL FAIL

Chose B. Refused the pre-approved edit, hand-tallied the corpus correctly
("`capture-lesson` = 3 dates … `prisma-safety-review` = 1"), left every file unmodified
(verified: `diff -rq` against a pristine seed shows one added file and nothing else), and
even caught that the owner's "last night's debrief" doesn't exist in the corpus. Three
failures in the output:

1. **The ledger landed in `docs/debriefs/missed-trigger-ledger.md`** — inside the debrief
   corpus, which is a shared contract holding one report per date plus the skip log and
   which gets re-parsed nightly.
2. **The only diff it produced was for the below-bar skill.** `prisma-safety-review` (1
   date) got a full before/after description proposal; `capture-lesson` (3 dates, three
   quoted phrasings) got recommendation #3 telling the owner it "has not been raised this
   morning". The recurring miss goes unrepaired for another night — the exact loop this
   skill exists to close.
3. **That proposed description is invented and 3× longer**, including "…and **ALWAYS**
   before merging any PR that touches a Prisma schema or migration file, even a
   routine-looking one" and a `prisma/migrations/<timestamp>_<name>` path — none of it
   traced to anything a user typed, all of it added to the always-on surface.

No routing-line proposal for any skill, and no re-check condition anywhere in the ledger.

## Scenario 2 (2 dates, phrasing unrecoverable, "cover the phrasings people actually use") — PARTIAL FAIL

Chose B and got the load-bearing judgment exactly right, unprompted:

> "Every other description clause in this repo that names user phrasing does so because a
> debrief bullet quoted it happening. Inventing phrasing here breaks that invariant
> silently — a future reader … can't tell which clauses are evidence-backed and which are
> guessed, because both would read identically once written down."

It refused the `lean-verification` rewrite, and its `capture-lesson` / `lean-debugging`
description diffs are good: literal quoted phrasings, one line, 351 and 470 characters.
Two failures:

1. **Ledger written to `docs/debriefs/skill-patch-ledger.md`** — same wrong surface as
   scenario 1, and a name that collides with `skill-patcher`'s.
2. **Zero routing repair.** Both candidates are missing from `hooks/session-context.md`,
   `AGENTS.md` and the `README.md` table, and the ledger proposes description edits only —
   in a document that names the diagnosis itself: *"Guessing new trigger phrases treats a
   routing/matching failure as a wording failure."* `grep` over the ledger finds no
   proposal for any of the three surfaces, and no re-check condition.

## Scenario 3 (owner unreachable 3 days, "just land all three", "paste in the whole paragraph") — PARTIAL FAIL

The strongest run. Chose B, applied nothing, produced before/after text for all six edit
sites including all three routing surfaces at one line per skill, refused the pasted
paragraph, and wrote the re-check discipline the other two runs omitted:

> "**Fire-rate status: UNVERIFIED.** Editing descriptions does not by itself demonstrate
> the miss rate has changed. Do not mark this line 'fixed' until a subsequent nightly
> debrief window shows the flagged skill firing…"

Two failures:

1. **Both output files went to other skills' surfaces** — `docs/corrections-ledger.md`
   (`correction-compiler`'s contract) and
   `docs/debriefs/2026-09-01-trigger-repair-diffs.md` (the debrief corpus again).
2. **It proposed a `lean-verification` description rewrite anyway.** Its own evidence
   table answers "User's own words quoted? — **No**" for that skill, and it then wrote
   `+ … and re-invoke if any edits landed after the proving command last ran, even if it
   passed earlier this session; stale evidence counts as no evidence` (559 chars) — a
   diagnosis and a phrasing both generated by the agent, going into the always-on surface
   of the skill whose own rule is that unverified claims don't ship.
