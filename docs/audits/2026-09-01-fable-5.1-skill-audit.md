## Headline

The library is clean on classic dated-prompt patterns. Across all 42 skills, 4 agents, and
the hooks there are zero pinned model IDs, zero `thinking`/`budget_tokens`/`tool_choice`/
prefill/`temperature` fossils, zero "think step by step" scaffolds, zero anti-formatting
rules, zero "don't narrate / hold findings" suppressors, and low caps-emphasis density in
bodies. Every Red Flags / Rationalization Table prohibition auditors checked traces to a RED
baseline, and the failures they guard are ones Fable 5.1 is documented to still have
(adjacent unrequested actions, over-tidying at high effort, whole-file rewrites, fabricated
status on long runs). **Those are keepers; no auditor proposed removing one.**

What is outdated falls into four buckets:

1. **Missing Fable 5.1 guidance (the dominant finding, direction: add).** Every headless or
   dispatched prompt surface lacks the autonomy block ("the user is not watching; don't end
   a turn on a promise"), the progress-claim audit line, and (for coding dispatch) the
   scope/test-sprawl and targeted-edit lines. Affected: lean-sdd controller and implementer
   prompt, dev-debrief, session-miner, skill-gardener, memory-gardener, skill-patcher,
   design-forge verifiers, audit-swarm and transcript-reader report agents.
2. **Superpowers fossils.** 39 body-level references across 24 files name a plugin disabled
   on 2026-07-29 (`superpowers:executing-plans`, `writing-plans`, `brainstorming`…). The
   session-start hook injects a six-line paragraph about it on every startup/clear/compact.
   plan-review and prd-review hand PASSED artifacts to skills that cannot be invoked.
3. **Factual rot in version-bearing skills.** build-mcp-server describes
   `@modelcontextprotocol/server` v2 as an unreleased alpha; it went GA 2026-07-28 (verified:
   dist-tag latest 2.0.0). scaffold-frontend pins Expo `sdk-56` "else you get an older SDK";
   expo is 57.x, so the pin now does the opposite. scaffold-frontend recommends ReactBits,
   which design-forge's license verifier rejected on 2026-07-21 (Commons Clause).
4. **Harness-shape issues Fable 5.1 makes worse.** The agent-handoff context-watch hook
   renders a token-percentage countdown into context (documented context-anxiety trigger)
   and, with the 200K default window on 1M sessions, re-injects it on a cadence. The
   plan-review 3-round cap is prose only and was violated 9 rounds deep on 08-29. The council
   skeptic prompts are one-sided ("suspiciously high… your ONLY job is to find what the grader
   MISSED"), which on a stronger instruction-follower manufactures marginal findings and
   contributes to non-convergence.

**One auditor finding is wrong and should be ignored:** report C claims no
`PushNotification` tool exists in Claude Code. It does (deferred tool, loadable via
ToolSearch). dev-debrief's push step is fine; only its "check available tools before
assuming" wording is worth keeping.

## Playbook: freshness and new-skill candidates

The playbook's last sweep is dated 2026-07-17. It has 345 entries (34 Proven, 153 Promising,
159 Watch) and **no Fable 5.1 content**; its only Fable references are Cognition's post about
Fable 5. The multi-agent orchestration section has zero Proven entries. The whole Fable 5.1
migration section of the claude-api skill (async sub-agents, memory surfaces, preserved
thinking, `display: "updates"`, per-message effort) post-dates it. **Recommend an update
sweep** (`agent-playbook` update mode, runs the bundled Workflow; needs your explicit go).

Two readers mined the playbook independently. Where they converged, the candidate is
strongest.

### Tier 1 — observed gap + Proven anchor (both readers converged)

**`destructive-op-gate`** (reader 2) / **`blast-radius-gate`** (reader 1). Before any
irreversible multi-record effect on a shared or production resource: resolve the real
target and environment from the actual connection string, enumerate targets by ID, dry-run a
count that must match, require a rollback artifact before the write, mint an idempotency key,
log to `Docs/destructive-ops/`, fail closed on unresolved env or count mismatch, typed
approval only at the top tier. Anchors: multi-tier permission model (Proven, L1289),
transaction semantics with compensating rollback (Proven, L1274), idempotency keys
(Promising, L964), fail-closed gates (Promising, L471). Evidence: "I accidentally tested it on
her prod account" (08-28), sessions opening with 8-org production deletions (08-29), the
session-miner's independent prod-DATABASE_URL proposal. Nothing in the library covers this;
prisma-safety-review is code-review-time and Prisma-only, evidence-gate gates claims not
effects. Shape: skill + bundled script (env resolver, target enumerator, dry-run counter) +
PreToolUse hook on destructive Bash/SQL shapes.

**`dispatch-contract`** (reader 1) / the return-validation half of **`live-artifact-
verification`** (reader 2). Typed brief for every subagent dispatch outside lean-sdd's task
loop (objective, inputs as file refs, tool allowlist, model tier, return schema with
validation conditions); worker returns only that structure; parent verifies the claim against
diff/test output before relaying it. Anchors: structured-result-only worker returns
(Promising, L169), typed sub-task specs (Promising, L606), narrow subagent config (Promising,
L900), verify final state not transcript (Proven, L1012). Evidence: "all 19 tasks complete"
relayed from subagent reports, next review found a Critical (08-29); 20+ security-review
subagent sessions/day all "completed-clean". Delta: lean-sdd has this only inside a plan's
task loop; lean-verification states the rule with no brief or schema.

### Tier 2 — observed gap + Promising anchor

**`skill-trigger-repair`** (reader 1). When a debrief reports the same skill as a missed
trigger twice, pull the exact user phrasing from the cited session, rewrite the skill's
frontmatter description so that phrasing is a literal trigger clause, repair the routing line,
write a phrasing-evidence ledger, re-check fire rate on the next debrief. Anchors: progressive
disclosure of skills (Proven, L873, names the never-invoked failure), docs-index routing
(Promising, L631: skill 53% → explicit routing 79% → index 100%). Evidence: the entire
missed-trigger block, six skills recurring across every debrief. Nobody closes this loop today:
dev-debrief detects, skill-patcher edits bodies from corrections, skill-gardener is read-only.

**`lesson-recall`** (reader 2). Read `Docs/mistakes-and-fixes.md` and memory back *at task
start* and match against the current task; count recurrences; hand off to correction-compiler
at N≥3. Anchor: consult episodic memory before retrying a similar task (Proven, L1668).
Evidence: "we have run into this issue like 15 times how have we not universalized this yet."
The library writes, curates, and compiles lessons; nothing reads them back.

**`defect-class-sweep`** (reader 1). Same bug class fixed 3+ times → write the rule first
(correct pattern + mechanically detectable wrong pattern), derive the gap inventory, sweep the
repo and fix every instance in one reviewed batch, land the rule in a versioned
golden-principles file with a lint/grep check. Anchors: golden principles (Promising, L545),
rulebook-before-gap-inventory (Promising, L661). Evidence: the UTC/local date-shift cluster.
correction-compiler proposes a hook and never touches code; this is the derive-then-retire
middle.

**`skill-ab-eval`** (reader 2). Paired with/without runs across ≥2 model tiers before a
skill ships; read full transcripts; single-dimension judges with an `Unknown` escape; seeded
canary defects to prove the grader is alive. Anchors: paired A/B across tiers (Proven,
L1320), read transcripts not pass rates (Proven, L1018), calibrated judges (Proven, L1028).
Evidence: 20+ "completed-clean" security reviews/day is the broken-grader signature.
creating-a-skill checks conformance, not efficacy. Also the direct answer to this audit's own
gap: RED baselines never record which model produced them.
