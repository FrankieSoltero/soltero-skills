# Instagram brief

Fill this with the user when there is no code project to read (or when
`--brief` is given). Every field feeds `facts.md`. An empty field is a
question to ask, never a field to infer — the invented answers are the ones
that ship.

## Product / offer

What it is, in the user's own words. If it is an offer, the exact terms as
they stated them — what is included, what is not, dates, times, days.

> Scope is a claim. "Half-price drafts" is not "every draft on the wall".
> Write down what they said; do not widen it.

## Audience

Who this is for, and what they already know.

## Goal + CTA

One goal. **One** CTA, in the words it will appear in.

## Given facts

One per line, each usable on screen or in the caption as written. Numbers,
features, policies, dates. Anything the user asserts in conversation without
a source is still a fact **candidate** — it goes in marked
`[CONFIRM: source?]`.

- Testimonials, quotes, ratings, "people keep telling us…": source or name
  required, or it cannot be used at all (see
  [../references/content-types.md](../references/content-types.md)).
- Unreleased, internal, or flagged information: mark `[CONFIRM: public?]`.

## Brand colors / fonts

Hex values and font names. Logo file path if there is one.

## Asset paths

Every image, video, or logo, as a full path.

> Each path is checked against disk in Step 1 and must exist **exactly** as
> written. A missing asset stops the run and comes back to the user as a
> question — it is not resolved by using a similarly named file or by
> designing around the gap.

## Voice

Where the voice comes from: an existing post, a landing page, a style note,
or "match the product copy".

## Constraints

Anything fixed — a deadline, a legally required line, a word that must not
appear.
